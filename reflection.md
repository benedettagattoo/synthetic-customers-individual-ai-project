# Reflection

Benedetta Gatto (3341868) · Individual AI Project, 20595 Business Analytics · Idea 12, Synthetic customers

In this project I used the OpenCode agent to build synthetic customers from Twin-2K-500 respondents and compare their purchase answers with the real ones, working in a plan–approve–check loop and logging every choice in plan.md and every error in mistakes.md. It showed me that producing plausible explanations is not the same as producing reliable research.

**What went wrong, and why.** First, written descriptions drifted from computed results: the agent reported an overlap of 135 columns when the smaller file had only 127, and described non-consecutive columns as continuous ranges even after an explicit rule had been added. Its explanations were not checked against the evidence, and instructions alone did not guarantee compliance. More consequential, the analysis initially treated survey columns as fixed products, although they were display positions randomized for each respondent. The dataset described the first respondent's products and prices as if they applied to everyone, and neither the initial report nor the plan questioned it; the mapping was resolved only by testing both interpretations against the raw data.

Code that ran was not code that worked. A script was declared ready after a syntax check although it would have crashed, and a comparison script used real responses for both groups, producing apparently perfect agreement. Validation itself became a source of error: exact-string price matching rejected valid answers (for example, prices without the dollar sign), and the first fix covered only the formats seen with one model, so the problem reappeared with another. I share responsibility for a fallback rule I approved, which switched the output schema for about 97% of calls because of a formatting difference. In its interpretations the agent moved too quickly from coefficients to conclusions: it treated artefacts of the linear probability model as findings, read narrow synthetic confidence intervals as stronger evidence, and read wide intervals as similarity.

Finally, a supposedly independent agent run had read the previous choices log and copied it. Repeated in a clean folder with the same model, the agent made different choices (prices in dollars, no free-price indicator, HC1 intervals), reproduced the demand curves in all 550 cells, but made one borderline product testable: analysis choices can move a verdict. A second AI assistant also supplied a wrong product mapping, and I wrongly blamed the agent for a documented statement, so agreement between tools is not independent confirmation, and human review can fail too.

**What it implies for next time.** What protected the results was not that scripts ran but dry runs, small pilots, checks of joins, saving every raw response and independent recomputation. The step pattern of the synthetic answers was already visible in the 25-call pilot, so pilots should also decide whether scaling up is worth its cost. Next time I would give the agent bounded tasks, test validators on real outputs of each model, keep earlier choices out of reach when testing independence, and check every conclusion against the design and its uncertainty. The agent was most useful when it tested alternatives, acknowledged uncertainty and asked about ambiguous instructions; I would trust it on the basis of that behaviour and of verified outputs, not of fluency or confidence.
